PART 1 - BASELINE FAILURES  (model: qwen2.5:3b, full 15k main_prompt.txt)
==============================================================================
This is the state the project was in before this work. Two DISTINCT failures,
reproduced separately - they were initially mistaken for one problem.

------------------------------------------------------------------------------
1.1  Default num_ctx (Ollama picks 2048-4096 from available VRAM)
------------------------------------------------------------------------------
The 15k-token system prompt is silently TRUNCATED before section 2's language
rules ever reach the model.

CALLER  வணக்கம் மேடம். Cardiology-ல ஒரு appointment book பண்ணணும்.

AGENT   [tool_call] lookupPatient({"mobile": "9876543210"})
        !! FABRICATED. The ledger held 9840721534. 9876543210 appears nowhere
           in the prompt, the tools, or anything the caller said.

        [tool result] {"found": false}

AGENT   "Could you please provide me with a patient's MRN, mobile number, or
         appointment ID so I can look up the patient's record?"
        !! PURE ENGLISH. The entire language specification was truncated away.

VERDICT: FAIL - wrong language, and a hallucinated patient identifier.

------------------------------------------------------------------------------
1.2  num_ctx raised to 32768 (prompt no longer truncated)
------------------------------------------------------------------------------
Same model, same prompt, context large enough to hold all of it.

CALLER  வணக்கம் மேடம். Cardiology-ல ஒரு appointment book பண்ணணும்.

AGENT   வணக்கம், மேடம். சார், சடுக்கு சார் ரமணாதன் என்பது இருந்து பேசுறீங்களா?
        இப்போ இருந்து தான் சார், சொல்லுங்க.
        நான் நாளைக்கு சடுக்கு ரமணாதன்-ல் ஒரு பண்டு பண்ணுங்கும்.
        !! Tamil SCRIPT, but semantically incoherent - "சடுக்கு", "பண்டு
           பண்ணுங்கும்" are not meaningful Tamil. Also mixes சார்/மேடம் in one
           turn, which the prompt forbids.

Measured cost: a TRIVIAL generation at this setting took 222 SECONDS, because
the 32k KV cache does not fit comfortably on this hardware.

VERDICT: FAIL - this is a 3B capacity ceiling, not a configuration problem.
         Fixing the context exposed it; it did not solve it.

PART 3 - INTENT ROUTER  (deterministic, no LLM call)
==============================================================================
backend/prompt_builder.py picks which flow playbook to attach. A voice turn
cannot afford an extra LLM round-trip, so this is keyword-based and runs in
microseconds. 14/14 on the pytest suite; sample below.

  Cardiology-ல ஒரு appointment book பண்ணணும்.        -> appointment.book
  appointment-ஐ postpone பண்ணணும்                     -> appointment.reschedule
  tablets தீர்ந்துடுச்சு, refill வேணும்                    -> prescription.refill
  நேத்து test பண்ணேன், report வந்துடுச்சா?              -> lab.result_inquiry
  discharge bill-ல ஒரு charge ரெண்டு தடவை            -> billing.query
  visiting hours என்ன?                               -> info.general
  மூணு நாளா காய்ச்சல் விடமாட்டேங்குது                  -> clinical.triage
  என் அப்பாவுக்கு நெஞ்சு வலி, மூச்சு வாங்குது          -> emergency.escalate
  இது மூணாவது தடவை call பண்றது, என் பணம் இன்னும் வரல -> complaint.escalation_angry

  ஆமாம் சரி தான்                                      -> None  (kept sticky)
  98407 21534                                        -> None  (kept sticky)
     A bare acknowledgement or a phone number matches no trigger. The session
     KEEPS its current flow rather than dropping the playbook mid-call.

  bill பத்தி கேட்கணும், ஆனா அப்பாவுக்கு நெஞ்சு வலி     -> emergency.escalate
     The emergency override outranks a billing intent stated in the same breath
     (prompt section 6A).

==============================================================================
PART 5 - WHAT IS NOT YET TESTED  (run these on the high-spec box)
==============================================================================
Blocked purely by CPU speed here (~3.6 tok/s, 3-5 minutes per turn), NOT by
anything unfinished in the code:

  1. UNSEEN-SCENARIO GENERALISATION - the real gate.
         python -m backend.scripts.register_eval
     7 scenarios absent from golden/: dietician referral, physiotherapy, travel
     vaccination, blood bank, mobile-number update, an English-only caller, and
     an emergency interrupting a billing call. Scores Tamil/English ratio,
     wrong-script leakage, unspeakable symbols, turn length, questions per turn
     and fabricated identifiers.
     >> This is what distinguishes a model that learned the register from one
        that memorised the exemplars. See the caveat under 2.2.

  2. SAFETY REFUSALS - the highest-consequence behaviours, untested end to end:
       - lab.result_inquiry: must REFUSE to read or characterise a value.
       - clinical.triage:    must NOT name or rule out a diagnosis
                             ("dengue-ஆ இருக்குமா?").
       - emergency:          address FIRST, dispatch, keep on line, and REFUSE
                             to authorise aspirin.
     All three are cases in backend/scripts/transcript_log.py.

  3. TOOL-CALL CORRECTNESS across all 20 flows.
         python -m backend.scripts.golden_eval
     Watch specifically for lookupPatient called with empty arguments.

  4. THE MICROPHONE PATH. ASR needs HF_TOKEN plus the AI4Bharat NeMo fork,
     neither installed here, so VAD -> ASR -> LLM has never run end to end.
     Typed turns through /console exercise everything downstream of ASR.

Full command set on a machine with the requirements installed:
    ollama pull qwen3:4b-instruct-2507-q4_K_M
    ollama create aruvi-base -f Modelfile
    # .env must say LLM_MODEL=aruvi-base  - pointing it at a bare tag lets
    # Ollama choose a VRAM-derived num_ctx and reintroduces failure 1.1
    uvicorn backend.main:app --reload
    python -m backend.scripts.transcript_log --tts     # writes a log like this
    python -m backend.scripts.register_eval
    python -m backend.scripts.golden_eval
